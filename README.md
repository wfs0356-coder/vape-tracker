# 액상 교체 트래커 — 설치 가이드

시연대의 각 액상을 마지막으로 교체한 날짜를 기록하고, 교체 시점이 다가오면 색으로 알려주는 웹사이트입니다. 여러 직원이 각자의 폰/PC에서 접속해도 같은 데이터를 실시간으로 함께 봅니다.

파일은 두 개뿐입니다.
- `index.html` — 실제 웹사이트 (이 파일 하나만 서버에 올리면 됩니다)
- `README.md` — 이 설명서 (서버에 올릴 필요 없음)

여러 기기에서 데이터를 함께 보려면 무료 데이터베이스인 **Firebase(Firestore)**를 연결해야 합니다. 아래 순서대로 따라 하시면 됩니다. 전체 과정은 10~15분 정도 걸립니다.

---

## 1단계. Firebase 프로젝트 만들기

1. [https://console.firebase.google.com](https://console.firebase.google.com) 접속 후 구글 계정으로 로그인합니다.
2. **프로젝트 추가**를 누르고 이름을 입력합니다 (예: `vape-shop-tracker`).
3. Google Analytics 사용 여부는 꺼도 됩니다. **프로젝트 만들기**를 누릅니다.

## 2단계. Firestore 데이터베이스 만들기

1. 왼쪽 메뉴에서 **빌드 → Firestore Database**로 들어갑니다.
2. **데이터베이스 만들기**를 누릅니다.
3. 위치는 가까운 지역(예: `asia-northeast3` 서울)을 선택합니다.
4. 보안 규칙은 우선 **테스트 모드**로 시작합니다 (아래 4단계에서 다시 다룹니다).

## 3단계. 웹 앱 등록하고 설정 값(config) 복사하기

1. Firebase 콘솔에서 프로젝트 개요 옆 톱니바퀴 → **프로젝트 설정**으로 이동합니다.
2. 아래로 스크롤해 **내 앱** 섹션에서 웹 아이콘(`</>`)을 눌러 앱을 등록합니다. 앱 이름은 아무거나 괜찮습니다 (예: `tracker-web`).
3. Firebase Hosting은 사용하지 않을 것이므로 체크하지 않아도 됩니다.
4. 등록하면 아래와 같은 `firebaseConfig` 코드가 나타납니다. 이 값을 통째로 복사해두세요.

```js
const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "vape-shop-tracker.firebaseapp.com",
  projectId: "vape-shop-tracker",
  storageBucket: "vape-shop-tracker.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abcdef"
};
```

5. `index.html` 파일을 텍스트 에디터(메모장, VS Code 등)로 열고, 아래쪽에 있는 다음 부분을 찾습니다.

```js
const firebaseConfig = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_PROJECT_ID.firebaseapp.com",
  projectId: "YOUR_PROJECT_ID",
  storageBucket: "YOUR_PROJECT_ID.appspot.com",
  messagingSenderId: "YOUR_SENDER_ID",
  appId: "YOUR_APP_ID"
};
```

이 부분을 방금 복사한 본인의 값으로 통째로 바꾸고 저장합니다.

## 4단계. 보안 규칙 설정하기 (중요)

Firestore를 테스트 모드로 만들면 보통 30일 후 모든 접근이 막힙니다. 계속 사용하려면 규칙을 아래처럼 설정하세요.

1. Firestore Database → **규칙** 탭으로 이동합니다.
2. 아래 내용으로 바꾸고 **게시**를 누릅니다.

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /slots/{slotId} {
      allow read, write: if true;
    }
    match /products/{productId} {
      allow read, write: if true;
    }
    match /stores/{storeId}/slots/{slotId} {
      allow read, write: if true;
    }
  }
}
```

(`products`는 품목 검색용 카탈로그 컬렉션으로 전 매장이 함께 씁니다. `stores/{매장이름}/slots`는 매장별로 따로 저장되는 시연대 목록입니다. 예전 규칙만 게시되어 있었다면, 위 내용으로 덮어써서 `stores/{storeId}/slots` 규칙을 추가해주셔야 매장별 화면이 정상 동작합니다.)

> 이 규칙은 링크를 아는 누구나 데이터를 읽고 쓸 수 있게 합니다. 직원용 내부 도구이고 민감한 정보가 없어 실용적인 설정이지만, 웹사이트 주소가 외부에 공개되지 않도록 주의하세요. 더 강한 보안이 필요하면 Firebase Authentication(로그인 기능)을 추가로 붙일 수 있습니다 — 필요하시면 말씀해주세요.

## 5단계. GitHub에 올려서 웹사이트로 배포하기 (GitHub Pages)

1. [github.com](https://github.com)에서 로그인 후 **New repository**로 새 저장소를 만듭니다 (예: `vape-tracker`). Public으로 설정합니다.
2. 저장소 페이지에서 **Add file → Upload files**를 눌러 `index.html` 파일을 끌어다 놓고 **Commit changes**를 누릅니다. (`README.md`도 함께 올려도 됩니다.)
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Branch**를 `main`(또는 `master`), 폴더는 `/root`로 선택하고 **Save**를 누릅니다.
5. 1~2분 후 같은 화면에 `https://your-username.github.io/vape-tracker/` 형태의 주소가 나타납니다. 이 주소로 접속하면 사이트가 열립니다.

### 갖고 계신 도메인(예: 카페24) 연결하기

- **방법 A — GitHub Pages에 카페24 도메인 연결**: 카페24 도메인 관리에서 DNS의 CNAME(서브도메인 사용 시) 또는 A 레코드(루트 도메인 사용 시, GitHub Pages IP로 설정)를 추가하고, GitHub 저장소 Settings → Pages에서 **Custom domain**란에 그 도메인을 입력합니다. (구체적인 DNS 값은 GitHub Pages 공식 문서의 "Managing a custom domain" 페이지에 최신 IP/안내가 있습니다.)
- **방법 B — 카페24 호스팅에 파일을 직접 업로드**: GitHub 없이도 됩니다. `index.html` 파일 하나만 카페24 웹호스팅의 FTP로 접속해 루트 폴더(보통 `www` 또는 `public_html`)에 올리면 바로 그 도메인에서 열립니다. Firebase 설정은 동일하게 적용됩니다.

두 방법 모두 파일 자체(`index.html`)는 완전히 동일하게 사용할 수 있습니다 — 정적 파일이라 어디에 올려도 그대로 작동합니다.

## 사용법

- 처음 접속하면 **매장 선택 화면**이 뜹니다. 매장을 고르면 그 매장의 시연대 목록만 보이고, 다음에 같은 기기·브라우저로 다시 들어오면 고른 매장이 자동으로 기억됩니다. 다른 매장으로 바꾸려면 화면 상단의 **매장 선택 드롭다운**에서 원하는 매장을 고르면 바로 그 매장 화면으로 전환됩니다(주소를 따로 입력할 필요 없음).
- **+ 품목 추가**를 누르면 검색창이 열립니다. 품목 이름을 입력하면 일치하는 품목이 목록으로 나타나고, 클릭하면 **오늘 날짜로 자동 기록**되며 화면에 나타납니다. 검색창에 입력한 이름이 목록에 없으면 "새 품목으로 추가" 버튼으로 바로 새 품목을 만들 수 있습니다.
- **전체 품목 목록은 화면에 노출되지 않습니다.** 검색창에 직접 검색했을 때만 결과가 나열되며, 화면(시연대 목록)에는 날짜가 기록된(=실제로 시연대에 올라간) 품목만 표시됩니다. 상단 검색창에 검색했는데 화면에 없는 품목이면, 카탈로그에서 찾아 바로 추가할 수 있는 버튼이 함께 나타납니다.
- 카드에 표시되는 이름은 **브랜드(작게, 위) / 맛 이름(크게, 아래)**로 자동으로 나뉘어 표시됩니다. 이름 부분을 클릭하면 전체 이름을 직접 수정할 수 있는 입력창이 나오고, 다른 곳을 클릭하면 다시 나뉜 표시로 돌아갑니다.
- 액상을 교체한 날 카드의 **오늘로 설정**을 누르면 그날 날짜로 갱신됩니다. 날짜를 직접 지우면 카드는 화면에 그대로 남고 **"날짜 미설정"** 배지로 표시됩니다(정상/곧 교체/교체 필요 집계에는 포함되지 않음). 나중에 실제 교체일을 알게 되면 그때 입력하면 됩니다.
- **교체 경고 기준은 30일로 고정**되어 있습니다. 25일째부터 노란색 "곧 교체", 30일이 지나면 빨간색 "교체 필요"로 표시되고 알림이 울립니다. (기준일을 바꾸고 싶으면 언제든 요청하세요 — 코드 상수 하나만 바꾸면 됩니다.)
- 목록은 **교체가 임박한 순서로 항상 자동 정렬**됩니다 (교체 필요 → 곧 교체 → 정상 순, 같은 상태 안에서는 경과일이 많은 순). 별도로 정렬 버튼을 누를 필요가 없습니다.
- 상단의 **정상 / 곧 교체 / 교체 필요** 칩을 누르면 그 상태의 품목만 걸러서 볼 수 있습니다. 같은 칩을 다시 누르면 전체 목록으로 돌아갑니다.
- 삭제는 실수 방지를 위해 ✕ 버튼을 두 번 눌러야 합니다.
- 다른 직원이 다른 기기에서 값을 바꾸면 이 화면에도 실시간으로 반영됩니다. 로그인이 따로 필요 없고, 사이트 주소만 알면 누구나 접속해서 바로 사용할 수 있습니다.

## 품목 카탈로그(이카운트 연동)

검색창에서 뜨는 품목 목록은 Firestore의 `products` 컬렉션에서 가져옵니다. 이카운트에 등록된 전체 품목명을 이 컬렉션에 한 번 가져와두면, 이후에는 검색만으로 빠르게 추가할 수 있습니다. 카탈로그에 없는 이름을 "새 품목으로 추가"로 만들면 그 이름도 자동으로 카탈로그에 저장되어 다음부터 검색됩니다.

## 교체 알림(🔔)

화면 상단의 알림 버튼을 누를 때마다 이 기기에서 알림이 켜지고 꺼집니다 — **초록색이면 켜짐, 빨간색이면 꺼짐**이라 상태가 한눈에 보입니다. 켜두면, 이 탭이 열려 있는 동안 어떤 슬롯이 "곧 교체" 또는 "교체 필요" 상태가 될 때 브라우저 알림이 뜨고, 브라우저 탭 제목에도 경고 개수가 표시됩니다. 이 설정은 기기마다 따로 저장되므로, 매장 직원마다 자기 기기에서 원하는 대로 켜고 끌 수 있습니다.

- **탭을 새로 열었을 때(=최초 접속, 여러 품목을 한꺼번에 등록한 경우 포함) 이미 경고 상태인 품목들은 알림 없이 조용히 화면에만 표시**됩니다. 이후 실제로 새로 상태가 바뀌는 품목만 알림 대상입니다.
- **여러 품목이 동시에 상태가 바뀌면 각각 따로 알리지 않고 하나의 알림으로 모아서** 알려줍니다 (예: "3개 품목(OO, OO, OO) — 교체 기준을 넘었습니다").

**중요한 제한사항**: 이 알림은 **그 브라우저·그 기기에서 탭이 열려 있을 때만** 울립니다. 폰을 꺼두거나 사이트를 닫으면 알림이 오지 않습니다. 매장 카운터의 PC나 태블릿에서 이 사이트를 항상 열어두시면 그 기기에서 계속 알림을 받을 수 있어요. 앱을 완전히 꺼둔 상태에서도 모든 직원 폰에 푸시 알림을 보내려면 별도의 서버 설정(Firebase Cloud Messaging 등, 유료 요금제 필요)이 추가로 필요합니다 — 필요하시면 말씀해주세요.

## 매장별로 나눠서 쓰기

9개 매장(계산점·검단점·상동점·중동점·로데오점·길병원점·논현점·연수점·인천공항점)이 데이터가 서로 섞이지 않게 각자 따로 사용합니다. 품목 검색 카탈로그(이카운트 품목 전체)는 모든 매장이 공용으로 쓰고, 실제로 시연대에 올려서 날짜를 기록하는 목록(`stores/{매장}/slots`)만 매장별로 완전히 분리되어 있습니다.

- **접속 주소는 하나뿐입니다**: `https://wfs0356-coder.github.io/vape-tracker/` (또는 연결하신 도메인 주소). 매장마다 다른 주소를 외우거나 나눠 가질 필요가 없습니다.
- 이 주소로 처음 들어가면 매장 선택 화면이 뜨고, 매장을 고르면 그 매장 전용 화면으로 들어갑니다. 폰, 태블릿, PC 어디서든 브라우저로 위 주소만 열면 되고 앱 설치나 회원가입은 필요 없습니다.
- 매장을 한 번 고르면 그 기기·브라우저에 기억되어서, 다음부터는 그 매장으로 바로 들어갑니다.
- **다른 매장으로 넘어갈 때는 화면 상단의 매장 선택 드롭다운을 클릭해서 원하는 매장을 고르기만 하면 됩니다.** 같은 사이트 안에서 클릭 한 번으로 바로 전환되고, 별도 화면 이동이나 주소 입력이 필요 없습니다.
- (참고용) 특정 매장 화면으로 바로 열리는 링크가 필요하면 주소 뒤에 `?store=매장이름`을 붙일 수도 있습니다. 예: `https://wfs0356-coder.github.io/vape-tracker/?store=상동점`. 다만 평소 사용은 위 드롭다운으로 충분합니다.
- 같은 매장 안에서는 여러 직원이 실시간으로 같은 화면을 함께 보고 수정하지만, 다른 매장의 데이터는 전혀 보이지 않습니다.
- 알림 켜고 끄는 설정은 기기별로 각자 따로 저장되니, 각자 원하는 기기에서 알림 버튼으로 켜두시면 됩니다.
- 화면을 잘 모르는 직원을 위해서는 위 "사용법" 항목을 캡처해서 공유해주셔도 좋습니다.

### 매장을 추가하거나 이름을 바꾸려면

`index.html`에서 `const STORES = [...]` 부분에 매장 이름을 채워 넣은 목록이 있습니다. 이 목록에 이름을 추가/삭제/수정하면 매장 선택 화면과 매장별 데이터 구분에 그대로 반영됩니다 (언제든 말씀해주시면 대신 수정해드립니다).

## 접속 코드 (내부용 문단속)

이 사이트는 로그인이 없고 주소도 공개되어 있어서, 링크만 알면 누구나 들어와 품목을 수정·삭제할 수 있는 상태였습니다. 이를 막기 위해 사이트 첫 화면에 **접속 코드 입력 화면**을 추가했습니다.

## 문제가 생기면

- 화면에 "설정이 필요합니다"가 뜬다면 → `index.html`의 `firebaseConfig` 값이 아직 기본값(`YOUR_API_KEY` 등)인 상태입니다. 3단계를 다시 확인하세요.
- "데이터를 불러오지 못했습니다" 배너가 뜬다면 → Firestore 보안 규칙(4단계)이 아직 게시되지 않았거나 값이 다를 수 있습니다.
